\section{Experiments}
\label{sec:experiments}

This section evaluates the role-shared semantic coordination framework in
simulation and on the hardware platform described below.  The section follows
the frozen experimental structure: setup, main results, baseline comparison,
failure analysis, ablation, and hardware experiments.  No numerical result is
reported in the current draft; every result cell and plotted measurement is
reserved by \textbf{***} until the corresponding runs are completed.

\subsection{Experiment Setup}
\label{sec:experiment_setup}

The experiments use the Isaac conveyor workspace shown in
Figure~\ref{fig:scenario}.  The setup contains heterogeneous manipulators,
static and moving targets, global visual observations, and the common
primitive-skill interface.  All compared methods receive the same scene and
task assets, observation interface, task-success criterion, local tracking
stack, safety stack, and physical execution stack.  The simulation conditions
are denoted \texttt{C1}--\texttt{C4} and cover static and dynamic scenes with
and without task-relevant semantic events.  The event labels are \texttt{E1}
for an online task update, \texttt{E2} for an external disturbance, and
\texttt{E3} for an execution failure confirmed from physical evidence.

The compared methods are Ours, End2End Planner, One Agent per Robot, and
COHERENT-Adapted.  The ablation methods are w/o Role Separation and w/o
Selective Replanning.  The evaluation records Task Success Rate, Subtask
Completion Rate (SCR), Makespan, Semantic Reasoning Time Ratio, Event Response
Time, and LLM Cost.  Task Success Rate measures completed tasks, SCR measures
verified primitive-subtask completion, Makespan measures elapsed execution
duration, Semantic Reasoning Time Ratio measures the fraction attributed to
semantic reasoning, Event Response Time measures the interval from event
detection to the next committed semantic update, and LLM Cost uses the common
token or call accounting protocol.  Trial counts and all numerical protocol
values are reserved for the final experiment log.

\subsection{Failure Analysis}
\label{sec:failure_analysis}

Failure analysis categorizes unsuccessful executions using four primary
failure types.  Invalid Capability denotes an assignment that does not satisfy
the selected manipulator's capability or reachable workspace, such as assigning
suction to place a basket outside its usable workspace.  Execution Anomaly
denotes a command whose physical execution condition changes, such as a
downstream suction pick after the target has moved too far away and left the
observation range.  Assignment Conflict denotes incompatible assignments in
one command batch, such as assigning both a Franka arm and a suction
manipulator to pick the same cola.  Task Timeout denotes failure to complete
within the allowed time, including repeated replanning that does not yield a
valid execution sequence.

Figure~\ref{fig:failure_analysis} provides a two-part layout for these
categories.  The upper part contains one schematic example for each failure
type.  The lower part reserves one donut chart for each compared method, with
the center label \texttt{Total: ***}.  The failure proportions remain
unmeasured and are not interpreted in this draft.
