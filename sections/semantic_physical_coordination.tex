\subsection{Update the Semantic State under Events}
\label{sec:semantic_physical_coordination}

Task-relevant events re-enter the shared semantic state, whereas continuous
physical evolution remains within manipulator-local execution.  Event handling
first determines where the state may be invalid and then invokes Planning only
for that scope.

\subsubsection{Identify the Affected Subtasks}
\label{sec:affected_subtasks}

The event types are defined in Eq.~\eqref{eq:semantic_events}.  A task update
changes the current instruction, an external disturbance is interpreted from
fresh visual evidence, and an execution failure is established by Verification.
The event then enters the Verification Role, which identifies the affected
primitive-subtask nodes:
\begin{equation}
 \mathcal{N}_k^{\mathrm{aff}}=
 \rho_V^{\mathrm{aff}}\bigl(
 e_k,\gamma,G,\mathcal{F},z\bigr),
 \label{eq:affected_subtasks}
\end{equation}
where $\mathcal{N}_k^{\mathrm{aff}}\subseteq\mathcal{N}$ contains the subtasks
whose task meaning, feasibility, execution status, or dependencies require
reconsideration.  This responsibility extends execution-effect verification to
event interpretation without introducing another semantic Role.

\subsubsection{Update the Semantic State}
\label{sec:update_affected_state}

Planning revises the graph and assignment within the identified scope through
the selective state update
\begin{equation}
 S_{\nu+1}^{\mathrm{sem}}=
 \mathcal{U}\!\left(
 S_\nu^{\mathrm{sem}},e_k,\mathcal{N}_k^{\mathrm{aff}}\right),
 \label{eq:semantic_state_update}
\end{equation}
where $\mathcal{U}$ returns one authoritative semantic state.  Nodes outside
$\mathcal{N}_k^{\mathrm{aff}}$ retain their previous assignments whenever those
assignments remain valid under the updated facts and capabilities.  Thus,
Verification determines where to reconsider, whereas Planning determines the
revised task structure and assignments.  An event does not imply global
replanning or interruption of valid unaffected execution.

\subsection{Dispatch and Execute Primitive Commands}
\label{sec:dispatch_execute}

\subsubsection{Construct Execution Commands}
\label{sec:construct_commands}

For node $n=(s_n,q_n,\eta_n)$ with assignment
$a(n)=(r_i,\kappa_n)$, the command passed to local execution is
\begin{equation}
 c_n\triangleq\bigl(s_n,q_n,\eta_n,r_i,\kappa_n\bigr),
 \label{eq:execution_command}
\end{equation}
where $\eta_n$ remains in the graph node for Verification and is not part of
the command.  After each verified completion, the dispatcher scans nodes that
have not completed or been sent.  A node is executable when every predecessor
$n_p$ linked by $(n_p,n)\in\mathcal{L}$ has status $\texttt{COMPLETED}$.
Independent executable commands form a concurrent command set
$\mathbf{c}_m=\{c_{n_1},c_{n_2},\cdots\}$.

\subsubsection{Execute Commands with Local Skills}
\label{sec:manipulator_local_execution}

The assigned local skill executes each command using the manipulator's current
visual observations and existing perception, tracking, and control stack.  The
command retains its target reference, so continuous target motion can be
handled locally without semantic replanning.  Local execution returns evidence
for Verification but cannot independently alter the task, graph, facts,
assignment, or execution status in the shared semantic state.

\subsection{Coordinate the Closed Loop}
\label{sec:closed_loop_coordination}

The task and initial visual observation first establish the role-shared
semantic state.  Planning decomposes the task and assigns each primitive
subtask to a compatible manipulator and local skill.  The dispatcher then
issues all independent executable commands, and local skills handle continuous
physical execution.  Fresh visual evidence allows Verification to confirm the
intended effects, after which newly executable graph nodes can be dispatched.

Normal verification advances the task without another Planning call.  When a
task update, external disturbance, or execution failure changes task-relevant
evidence, Verification identifies the affected scope and Planning selectively
revises its graph and assignments.  Valid unaffected execution continues when
possible.  Algorithm~\ref{alg:coordination} summarizes this closed loop.
