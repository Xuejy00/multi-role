\subsection{Update the Semantic State under Events}
\label{sec:semantic_physical_coordination}

Task-relevant events re-enter the shared semantic state, whereas continuous
physical evolution remains within manipulator-local execution.  Event handling
first determines where the state may be invalid and then invokes Planning only
for that scope.

\subsubsection{Identify the Affected Subtasks}
\label{sec:affected_subtasks}

The event types are defined in Eq.~\eqref{eq:semantic_events}.  A task update
changes the current instruction, an external disturbance is interpreted from
fresh visual evidence, and an execution failure is established by Verification.
The event then enters the Verification Role, which identifies the affected
assignment-aware primitive nodes:
\begin{equation}
 \mathcal{N}_k^{\mathrm{aff}}=
 \rho_V^{\mathrm{aff}}\bigl(
 e_k,\gamma,G_{\mathrm{assign}},\mathcal{F},z\bigr),
 \label{eq:affected_subtasks}
\end{equation}
where $\mathcal{N}_k^{\mathrm{aff}}\subseteq\mathcal{N}_{\mathrm{assign}}$
contains the nodes whose task meaning, feasibility, execution status, or
dependencies require reconsideration.  This responsibility extends
execution-effect verification to event interpretation without introducing
another semantic Role.

\subsubsection{Update the Semantic State}
\label{sec:update_affected_state}

Planning revises the assignment-aware primitive graph within the identified
scope through the selective state update
\begin{equation}
 S_{\nu+1}^{\mathrm{sem}}=
 \mathcal{U}\!\left(
 S_\nu^{\mathrm{sem}},e_k,\mathcal{N}_k^{\mathrm{aff}}\right),
 \label{eq:semantic_state_update}
\end{equation}
where $\mathcal{U}$ returns one authoritative semantic state.  Nodes outside
$\mathcal{N}_k^{\mathrm{aff}}$ retain their previous assignment-aware graph
entries whenever those entries remain valid under the updated facts,
capabilities, and manipulator set $R$.  Thus, Verification determines where
to reconsider, whereas Planning determines the revised
$G_{\mathrm{assign}}$.  An event does not imply global replanning or
interruption of valid unaffected execution.

\subsection{Dispatch and Execute Primitive Commands}
\label{sec:dispatch_execute}

\subsubsection{Construct Execution Commands}
\label{sec:construct_commands}

For an assignment-aware primitive node $n\in\mathcal{N}_{\mathrm{assign}}$, the
command passed to the robot interface is
\begin{equation}
 c_n=\phi_C(n),
 \qquad
 \phi_C:\mathcal{N}_{\mathrm{assign}}\rightarrow\mathcal{C},
 \label{eq:execution_command}
\end{equation}
where $\phi_C$ is the command construction function and $\mathcal{C}$ denotes
the executable command space, distinct from the per-manipulator capability
sets $\{\mathcal{C}_i\}_{i=1}^{N}$.  Although $n$ contains semantic execution
information, $c_n$ represents the executable command sent to the robot
interface.  At each execution step, nodes whose predecessor dependencies are
satisfied are selected into $\mathcal{N}_{\mathrm{exec}}$ and converted into
primitive command sets.  This is a temporary execution-time set rather than an
additional semantic state variable.  A node is executable when every
predecessor in $\mathrm{pred}_{\mathrm{assign}}(n)$ has status
$\texttt{COMPLETED}$.  Independent executable commands form a concurrent
command set $\mathbf{c}_m=\{c_{n_1},c_{n_2},\cdots\}$.

\subsubsection{Execute Commands and Verify Outcomes}
\label{sec:manipulator_local_execution}

The assigned local skill executes each command using the manipulator's current
visual observations and existing perception, tracking, and control stack.  The
command retains its target reference, so continuous target motion can be
handled locally without semantic replanning.  After primitive-subtask
execution, the latest observation updates the scene affordance information,
conceptually as $\mathcal{F}\rightarrow\mathcal{F}'$.  Local execution returns
evidence for Verification but cannot independently alter the task, graph,
facts, assignment-aware primitive graph, or execution status in the shared
semantic state.  Verification then extracts execution evidence from the
executed command and the current scene information:
\begin{equation}
 \eta_n=\rho_V^{e}\bigl(c_n,\mathcal{F}\bigr),
 \label{eq:verification_evidence}
\end{equation}
and determines the execution status from that evidence:
\begin{equation}
 z(n)=\rho_V^{z}\bigl(\eta_n\bigr).
 \label{eq:verification_status}
\end{equation}
Thus, Verification provides both semantic execution evidence and the status
used to advance the assignment-aware primitive graph.

\subsection{Coordinate the Closed Loop}
\label{sec:closed_loop_coordination}

The task and initial visual observation first establish the role-shared
semantic state.  Planning constructs the abstract graph $G$, materializes
$G_{\mathrm{assign}}$, and passes its executable nodes through $\phi_C$.  The
dispatcher then issues all independent executable commands, and local skills
handle continuous physical execution.  Verification extracts execution
evidence $\eta_n$ and maps it to status $z(n)$, after which newly executable
graph nodes can be dispatched.

Normal verification advances the task without another Planning call.  When a
task update, external disturbance, or execution failure changes task-relevant
evidence, Verification identifies the affected scope and Planning selectively
revises $G_{\mathrm{assign}}$.  Valid unaffected execution continues when
possible.  Thus, the closed loop follows
$G\rightarrow G_{\mathrm{assign}}\rightarrow\mathbf C\rightarrow z$.
Algorithm~\ref{alg:coordination} summarizes this closed loop.

\State $S_\nu^{\mathrm{sem}}
