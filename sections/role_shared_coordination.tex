\section{Method}
\label{sec:proposed_solution}

Figure~\ref{fig:method_overview} summarizes the information flow from the task
and visual observations to concurrent manipulator execution.  The method uses
one shared semantic state with explicit Affordance, Planning, and Verification
responsibilities.  The state is revised selectively when task-relevant evidence
changes, and its graph and assignments are compiled into primitive commands.

\subsection{Construct the Role-Shared Semantic State}
\label{sec:role_shared_coordination}

\subsubsection{Define the Shared Semantic State}
\label{sec:shared_semantic_state}

The common representation read and updated by the three Roles is
\begin{equation}
 S_\nu^{\mathrm{sem}}\triangleq
 \bigl(\gamma,G,\mathcal{F},a,z\bigr),
 \label{eq:semantic_state}
\end{equation}
where $\nu$ is the semantic version, $\gamma$ is the current task,
$\mathcal{F}$ contains task-relevant scene and feasibility facts, $a$ is the
manipulator-and-skill assignment, and $z$ records primitive-subtask status.
The dependency graph and each of its nodes are defined by
\begin{equation}
 G\triangleq\bigl(\mathcal{N},\mathcal{L}\bigr),
 \qquad
 n\triangleq\bigl(s_n,q_n,\eta_n\bigr),
 \label{eq:primitive_task_graph}
\end{equation}
where $\mathcal{N}$ is the set of primitive-subtask nodes, $\mathcal{L}$ is the
set of dependency links, $s_n$ is the primitive subtask, $q_n$ is its target,
and $\eta_n$ is its intended effect.  A link $(n_i,n_j)\in\mathcal{L}$ means
that $n_j$ depends on completion of $n_i$; capability and controller state are
not encoded in the graph.

\subsubsection{Assign Responsibilities to Three Semantic Roles}
\label{sec:semantic_roles}

The Roles jointly maintain the state in Eq.~\eqref{eq:semantic_state}; they are
responsibility interfaces rather than independent semantic systems.

\emph{Affordance Role.}  The Affordance Role maps a visual observation $o(t)$
to the task-relevant facts $\mathcal{F}$.  These facts describe object identity,
relations, affordances, and feasibility, but exclude continuous target pose,
velocity, and controller state.  Refreshing the facts is not by itself semantic
replanning.  During system initialization, objects detected in the visual
observation are established as semantic targets, and each semantic target is
maintained through a local tracking relation to the corresponding physical
object.  When a primitive skill executes a command, the skill uses the semantic
target to retrieve the currently tracked physical target state.  This preserves
the flow from semantic target to local tracking to skill execution without
adding target-state variables to the shared semantic representation.

\emph{Planning Role.}  Planning first decomposes the current task using the
facts and then assigns every primitive subtask using the heterogeneous
capabilities:
\begin{equation}
 \begin{aligned}
 G&=\rho_P^G\bigl(\gamma,\mathcal{F}\bigr),\\
 a&=\rho_P^a\!\left(
 G,\mathcal{F},\{\mathcal{C}_i\}_{i=1}^{N}\right),
 \end{aligned}
 \label{eq:planning_pipeline}
\end{equation}
where $a(n)=(r_i,\kappa_n)$ assigns node $n$ to manipulator $r_i$ and
a compatible local skill $\kappa_n$.  Both computations belong to one Planning
Role and preserve the order from task decomposition to capability-aware
assignment.

\emph{Verification Role.}  Verification evaluates the intended effect of an
executed primitive subtask against the current facts:
\begin{equation}
 z(n)=\rho_V\bigl(\mathcal{F},\eta_n\bigr),
 \label{eq:verification_map}
\end{equation}
where $z(n)$ becomes $\texttt{COMPLETED}$ only when the evidence supports
$\eta_n$.  Successful verification advances normal execution.  When a task
update, external disturbance, or execution failure requires semantic revision,
the Verification Role also interprets the event against the shared state and
identifies the affected primitive subtasks, as detailed in
Section~\ref{sec:affected_subtasks}.  Planning subsequently revises the graph
and assignment within that scope.

Together, the three Roles maintain complementary components of one shared
semantic state $S_\nu^{\mathrm{sem}}=(\gamma,G,\mathcal{F},a,z)$ in
Eq.~\eqref{eq:semantic_state}.  The Affordance Role maintains
the scene and feasibility facts $\mathcal{F}$, the Planning Role maintains the
task graph and capability-aware assignment $(G,a)$, and the Verification Role
maintains primitive-subtask status $z$.  The task instruction $\gamma$ remains
the common specification read by all three Roles; none of the Roles defines an
independent semantic state.
